# Edge and Networking Domain

This document describes the edge and networking stack that provides ingress, DNS, filtering, and security services for the homelab network. The stack consists of four primary components: Traefik (reverse proxy and ingress controller), Cloudflared (Cloudflare Tunnel connector), AdGuard Home with Unbound (DNS filtering and recursive resolution), and CrowdSec (security telemetry, bouncers, and dashboard).

## Traefik

Traefik serves as the core ingress, routing, and edge security stack. It handles HTTP(S) routing, middleware execution, and TLS termination for services exposed via Docker labels or dynamic configuration files.

Key responsibilities:
- Acts as the primary entry point for external traffic to services
- Provides routing based on host, path, and headers
- Executes middleware chains for authentication, rate limiting, headers, and security
- Manages TLS certificates via integrations (e.g., Let's Encrypt)
- Exposes a dashboard and API for configuration and monitoring

Integration points:
- Uses Docker provider (via a read-only socket proxy) to discover services
- Reads static configuration from `traefik.yml` and dynamic configuration from files in the `rules/` directory
- Integrates with CrowdSec via the official `crowdsec-bouncer-traefik-plugin` for IP blocking based on security decisions
- Uses `geoipupdate` to keep MaxMind GeoIP databases current for geolocation-based middleware
- Employs `traefik-manager` for a web UI to manage routes, middlewares, services, and certificates
- Utilizes `traefik-log-dashboard` and its agent for logging and visualization

Configuration layout:
- `traefik.yml` loads the file provider from `rules/`; no HTTP provider endpoint is enabled
- `rules/base.yml` contains repo-managed baseline middlewares, routers, and services
- `rules/crowdsec-manager.yml` is reserved for dynamic configuration generated by `crowdsec-manager`
- Traefik reads Docker through a read-only socket proxy (`tcp://dockerproxy-ro:2375`) to avoid permission issues
- The `traefik-manager` service provides a web UI for managing Traefik runtime files

CrowdSec Plugin:
- Traefik uses the official CrowdSec Traefik plugin loaded via `experimental.localPlugins` (not from the registry)
- The plugin sources are mounted read-only from `/mnt/user/appdata/traefik/plugins-local` into the container at `/plugins-local`
- The `crowdsec-bouncer` middleware is defined as a Compose config (not a file) to allow interpolation of `${CROWDSEC_FORWARDED_HEADERS_TRUSTED_IPS}` from `.env`
- The plugin reads the LAPI key from `/run/secrets/crowdsec-lapi-key` (supplied via `crowdsec_lapi_key` config)
- The middleware is applied only to `chain-external` and `chain-external-bypass` router chains; internal chains remain CrowdSec-free
- `CROWDSEC_FORWARDED_HEADERS_TRUSTED_IPS` must stay aligned with `websecure-external.forwardedHeaders.trustedIPs`

## Cloudflared

Cloudflared provides an optional Cloudflare Tunnel connector for exposing selected services safely without opening inbound firewall ports.

Key responsibilities:
- Establishes a secure tunnel from the homelab to Cloudflare's edge
- Allows services to be exposed via Cloudflare DNS without public IP addresses or port forwarding
- Supports load balancing, health checks, and access policies via Cloudflare Zero Trust

Services in the stack:
- `cloudflared`: The tunnel connector that maintains connections to Cloudflare
- `probe-busybox`: A helper container used to test tunnel connectivity

Upstream:
- Website: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/
- GitHub: https://github.com/cloudflare/cloudflared

Integration:
- Typically used alongside Traefik: services are exposed via Traefik internally, and Cloudflared tunnels specific Traefik routes (e.g., `traefik-dashboard` or specific services) to Cloudflare
- The tunnel configuration is managed via `cloudflared tunnel` commands, with credentials stored persistently

## AdGuard Home + Unbound

This stack provides DNS filtering and recursive DNS resolution for the homelab edge, combining AdGuard Home's blocking capabilities with Unbound's privacy-focused recursive resolution.

Key responsibilities:
- `adguard-home-unbound`: Runs AdGuard Home configured to use Unbound as its upstream DNS provider
- Provides network-wide ad blocking, tracker blocking, and malicious domain filtering
- Performs recursive DNS resolution (via Unbound) for domains not found in blocklists
- Supports DNS over TLS (DoT) and DNS over HTTPS (DoH) for upstream privacy
- Includes a replica synchronization mechanism (`adguard-home-sync`) for high availability with a secondary instance

Services:
- `adguard-home-sync`: Synchronizes configurations and blocklists between primary and replica AdGuard Home instances (optional for single-node setups)
- `adguard-home-unbound`: The main service providing DNS filtering and resolution

Upstream:
- AdGuard Home: https://adguard.com/en/adguard-home/overview.html (GitHub: https://github.com/AdguardTeam/AdGuardHome)
- AdGuard Home Sync: https://github.com/bakito/adguardhome-sync

Configuration Notes:
- The local replica URL is set to `http://adguard-home-unbound` (Docker service name) rather than a static IP, allowing container-to-container communication via the `smoonet` network
- The LAN-facing DNS address remains on the `br0` bridge (typically `192.0.2.3` in documentation examples)

## CrowdSec

CrowdSec provides security telemetry, bouncers, and a dashboard for perimeter defense and collaborative blocking.

Key responsibilities:
- `crowdsec`: The engine that analyzes logs, detects threats, and shares intelligence with the global CrowdSec network
- Generates decisions (bans) based on scenarios and sends them to bouncers
- `crowdsec-dashboard`: A Metabase-powered UI for visualizing alerts, decisions, and statistics
- `crowdsec-bouncer-prune`: Automatically removes old decisions from the database
- `crowdsec-manager`: Manages dynamic configuration for bouncers (e.g., updates Traefik's middleware configuration)
- `crowdsec-firewall-bouncer`: Applies blocks at the firewall level (e.g., via `nftables` or `iptables`)

State Database:
- CrowdSec stores machines, alerts, and decisions in a SQLite database at `appdata/crowdsec/data/crowdsec.db`
- The `crowdsec-dashboard` service mounts this same database for Metabase to read
- `USE_WAL=true` is enabled to allow concurrent reads and writes via write-ahead logging (WAL) mode, preventing `database is locked` errors

Traefik Integration:
- The Traefik remediation path is handled by the official `crowdsec-bouncer-traefik-plugin` inside the Traefik stack
- The `CROWDSEC_TRAEFIK_BOUNCER_API_KEY` is shared between the CrowdSec and Traefik stacks
- The `crowdsec` service registers the API key via the `BOUNCER_KEY_TRAEFIK` environment variable
- `crowdsec-manager` targets the shared `/etc/traefik/dynamic.yml` file to update bouncer configurations
- No standalone Traefik bouncer container is used; the plugin runs within the Traefik process

See the [CrowdSec stack README](/stacks/crowdsec/README.md) for detailed service descriptions.

## Integration and Flow

The edge and networking components work together to provide a secure, filtered, and observable network perimeter:

1. **Ingress and Traffic Flow**:
   - External requests arrive via Cloudflare (if using Cloudflared tunnels) or directly to the homelab's public IP
   - Traffic is routed to Traefik, which performs TLS termination (if not handled by Cloudflare) and applies middleware chains
   - Middlewares include CrowdSec bouncer (for external chains), rate limiting, headers, and authentication
   - Traefik forwards requests to the appropriate service Docker containers based on router rules

2. **DNS Resolution and Filtering**:
   - Devices on the LAN configure their DNS to point to the AdGuard Home instance (typically on `br0` at `192.0.2.3`)
   - DNS queries are processed by AdGuard Home, which checks blocklists and then forwards unresolved queries to Unbound for recursive resolution
   - AdGuard Home can also forward queries to upstream resolvers (e.g., Cloudflare, Quad9) with DoT/DoH for privacy
   - Blocked domains return NXDOMAIN or a configurable redirect IP

3. **Security Telemetry and Enforcement**:
   - Services (including Traefik via access logs) send logs to CrowdSec for analysis
   - CrowdSec matches logs against scenarios (e.g., brute force, path traversal) and generates decisions to ban offending IPs
   - Decisions are distributed to bouncers:
     - Traefik bouncer: Updates the `crowdsec-bouncer` middleware to block matching IPs at the edge
     - Firewall bouncer: Applies blocks at the network layer (e.g., `nftables`)
     - Dashboard: Displays alerts and decisions for monitoring
   - The `crowdsec-manager` service updates Traefik's dynamic configuration (`/etc/traefik/dynamic.yml`) to reflect new bouncer lists
   - `CROWDSEC_FORWARDED_HEADERS_TRUSTED_IPS` ensures Traefik uses the correct client IP when behind Cloudflared or other proxies

4. **High Availability and Reliability**:
   - AdGuard Home can be deployed in a primary-replica setup using `adguard-home-sync` for failover DNS
   - Traefik stores its configuration in files, allowing easy backup and restoration
   - CrowdSec's SQLite database with WAL mode supports concurrent access from the engine, dashboard, and bouncers
   - Cloudflared tunnels are persistent and automatically reestablish if connectivity is lost

This layered approach provides defense in depth: network-level filtering (AdGuard Home), application-level ingress control and security (Traefik with CrowdSec), and optional secure exposure via Cloudflare Tunnel (Cloudflared).
